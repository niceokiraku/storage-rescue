# StorageRescue

**途中で認識が切れてしまう障害 HDD から、自動で再接続しながらデータを救出する Windows 用ディスクイメージングツール**

障害のある HDD は、読み取り中に突然応答しなくなったり、USB 接続が切れて認識されなくなったりします。
StorageRescue は GNU ddrescue と同じ手順でディスクを丸ごとイメージ化し、切断を検知すると
**自動で再接続を試み、それでも戻らなければ「電源を入れ直してください」と画面で案内**します。
電源を入れ直せば、中断した位置から自動で作業を再開します。

> [!CAUTION]
> 本ソフトウェアは無保証です。障害ディスクは読み取りを続けるだけでも状態が悪化することがあります。
> **カチカチ・カコンといった異音がする場合や、重要なデータの場合は、使用せずにデータ復旧の専門業者へ相談してください。**

---

## 主な機能

- **GNU ddrescue 互換の救出アルゴリズム**
  Copying（前方向・逆方向）→ Trimming → Sweeping → Scraping → Retrying の順に、読みやすい領域から優先して救出します。
- **ddrescue 互換の mapfile**
  途中経過を ddrescue と同じ形式で保存します。いつ中断しても再開でき、Linux の `ddrescue` に引き継ぐこともできます。
- **切断の自動検知と復旧**
  1. 自動で再接続（約 10 秒）
  2. ハードウェア変更のスキャン（約 15 秒）
  3. 電源の入れ直しを画面・音・タスクバーの点滅で案内
     （電源 OFF → 待機のカウントダウン → 電源 ON → 回転安定待ち、の各段階を着脱検知で自動的に進めます）
- **同じディスクかを自動判定**
  モデル名・シリアル番号・容量で照合するので、再接続でドライブ番号が変わっても追跡できます。
- **Windows による勝手なアクセスを防止**
  作業中は入力ディスクをオフライン＋読み取り専用にし、再接続してもマウント（ドライブ文字の割り当て）されないようにします。
- **入力ディスクには一切書き込みません**
- **セクタマップ表示**：救出済み・未読・不良セクタなどを色分けして表示します。
- **ネットワーク通信は一切行いません**

## 動作環境

- Windows 10 / 11（64 bit）
- 管理者権限（ディスクを直接読み取るため。起動時に確認が表示されます）
- 救出するディスクの容量以上の空きがある、**別の**保存先ディスク

## 使い方

### 1. 準備

- 救出したい HDD を USB-SATA 変換アダプタなどで接続します。
  **HDD の電源を手元で入れ直せる構成**（AC アダプタ付きのケースやアダプタ、スイッチ付き電源タップなど）がおすすめです。
- 保存先には、救出したいディスクより大きな空き容量のある別のディスクを用意します。
- 他のアプリ（エクスプローラーのウィンドウ、バックアップソフトなど）で対象ディスクを開かないでください。

### 2. 設定して開始

1. `StorageRescue.exe` を起動し、**入力ディスク**を選びます（システムディスクは一覧に表示されません）。
2. **出力イメージ**の保存先を指定します（例: `D:\rescue\disk.img`）。mapfile は自動で `disk.img.map` になります。
3. 必要に応じてオプションを変更します（通常は初期値のままで構いません）。
4. **▶ 開始 / 再開** を押します。

### 3. 切断されたら

画面に案内が表示され、音が鳴ります。案内に従って HDD の電源を切り、待ち時間の後に電源を入れてください。
接続を検知すると自動で再開します。

> [!WARNING]
> 再接続時に「ドライブ ○: を使うにはフォーマットする必要があります」と表示されても、**絶対にフォーマットしないでください**（「キャンセル」を押してください）。

### 4. 中断と再開

**■ 停止** を押すと mapfile を保存して止まります。同じ出力イメージと mapfile を指定して **▶ 開始 / 再開** を押せば、続きから再開します。

### 5. 作業が終わったら

入力ディスクはオフラインのままになっています。通常の利用に戻す場合は、一覧でディスクを選んで **オンラインに戻す** を押してください。
救出したイメージは、データ復元ソフトで開いたり、別のディスクへ書き戻したりして利用します。
**障害ディスク本体を直接修復（chkdsk など）しようとしないでください。**

## オプション

### ddrescue 相当

| 引数 | 内容 | 初期値 |
|---|---|---|
| `-d` | 直接ディスクアクセス。OS のキャッシュを通さずに読み取ります | ON |
| `-N` | トリミング（読めなかったブロックの両端をセクタ単位で読み直す工程）を省略 | OFF |
| `--no-sweep` | スイープ（エラーで飛ばした領域を、飛ばさずに読み直す工程）を省略 | OFF |
| `-n` | スクレイピング（残りをセクタ単位で読む工程）を省略。まず読める所だけ救出したいときに | OFF |
| `-r` | 不良セクタを読み直す回数 | 0 |
| `-c` | 一度に読み取るセクタ数（0 = 自動: 64 KiB 分） | 0 |
| `-K` | 読み取り失敗時に先へ飛ばす量「初期値,最大値」（例: `64Ki,1Gi`） | 自動 |

画面上部に、同じ設定を Linux の GNU ddrescue で実行する場合のコマンドを表示します。

### 再接続

| 項目 | 内容 | 初期値 |
|---|---|---|
| 読み取りタイムアウト | この秒数以内に応答がなければ中止し、次へ進みます | 10 秒 |
| 電源 OFF 後の待ち | ディスクが完全に停止するまでの待ち時間 | 10 秒 |
| スピンアップ待ち | 電源 ON 後、回転が安定するまでの待ち時間 | 15 秒 |
| 開始時にオフライン＋読み取り専用化 | 再接続後も Windows にマウントさせない | ON |

## Linux の ddrescue に引き継ぐ

mapfile は GNU ddrescue と同じ形式です。途中まで StorageRescue で救出したイメージと mapfile を Linux にコピーし、
次のように実行すれば続きから処理できます（`/dev/sdX` は対象ディスク）。

```bash
ddrescue -d /dev/sdX disk.img disk.img.map
```

逆に、ddrescue で作成した mapfile から StorageRescue で再開することもできます。

## 既知の制限

- 実機で確認できている障害パターンや USB 変換アダプタの種類は限られます。
- 読み取りが OS の内部で完全に固まった場合、その I/O に使っていたメモリ（通常 64 KiB 程度）は安全のため解放せずに残します。また、固まった I/O が残っているとアプリの終了に時間がかかることがあります（HDD の電源を切ると終了できます）。
- 読み取りのタイムアウトは OS の I/O キャンセルに頼っているため、変換アダプタによっては指定した秒数より長くかかることがあります。
- 保存先はドライブ文字のあるボリュームである必要があります。
- ddrescue の一部の機能（`--min-read-rate` による低速領域のスキップ、fill モード、generate モードなど）には対応していません。

## ソースからのビルド

.NET 10 SDK が必要です。

```bash
dotnet build -c Release
```

配布用に、.NET ランタイムを同梱した単一の exe を `publish/` に作る場合（利用者側に .NET のインストールは不要になります）:

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -o publish
```

アイコンは `tools/MakeIcon.ps1` で生成しています。

## 謝辞

救出アルゴリズムと mapfile の形式は [GNU ddrescue](https://www.gnu.org/software/ddrescue/) のマニュアルを参考に、独自に実装しています。
StorageRescue は GNU ddrescue のソースコードを含まず、GNU プロジェクトとは関係ありません。
